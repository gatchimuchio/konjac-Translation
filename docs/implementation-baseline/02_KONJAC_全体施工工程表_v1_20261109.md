# KONJAC-Translation 全体系施工工程表 v1.0

- 文書ID：KJ-PLAN-20261109-02
- 制定：2026-11-09（JST）
- 主語：こんにゃく翻訳の全媒体・全環境を含む施工対象全体
- 目的：全数要求を一度の接続可能な施工系として成立させ、その後に局所・全体・環境別の検査で品質を閉じる。
- 正本依存：[01製品仕様書](01_KONJAC_統合製品実装仕様書_v1_20261109.md)。施工命令：[03Codex指示書](03_KONJAC_Codex全体系施工指示書_v1_20261109.md)。
- 状態：未施工開始の工程契約。先行Codex未コミット差分は未観測・未計上。

## P0 工程の不変条件

1. 全体系設計→全機能・全OS一括BUILD→全経路結線→局所QC→全体QC→対象別QA→Owner独立判断。既存の機能単位を逐次完成させる工程は失効させる。
2. W系列は責務別施工の並行作業索引、U系列は利用体験の検収索引、E系列は環境の適合索引である。いずれも逐次ローンチ・機能縮小・個別試運転のゲートではない。
3. 開発中の安全上必須検査、ビルド、型・依存検査は認める。機能一つを試運転して品質保証を閉じ、次機能へ進む反復に戻さない。
4. エンジンの実訳能力が欠けても、外部構成の全線施工は可能な範囲で続ける。ただし実訳受入・最終製品受入はBLOCKEDとし、偽の翻訳器で開通扱いしない。
5. 技術・処理場所・フレームワークの比較は同一要求の最適施工手段を選ぶ作業。言語自体を製品正本にしない。Rustは暫定共通基盤、将来AICompiler移管を保持する。
6. 実機の全数検証を要求せず、仕様適合と仮想・自動検証で成立範囲を閉じる。実機は観測確認であり、個別機体への場当たり調整を工程へ逆流させない。
7. 施工欠陥・未検証・未知を隠さず、変更理由・原証拠・Git履歴・不成立の原因を保存する。

## P3 検査・追跡母集団

### P3.1 A系列とU系列

- A01〜A07：製品主語、MINIDORA境界、第二エンジン禁止、媒体差替、追跡、能力停止、権利。
- U01〜U12：テキスト、往復会話、録音、デスクトップ字幕、会議通話、映像、Web、文書、画像、チャット、継続、API。
- 全19項目の状態列：要求定義／実装／結線／局所QC／全体QC／環境別QA／Owner受入。各列をPASS/FAIL/NOT RUN/BLOCKED/SUSPENDで独立管理する。
- 先行報告の「仕様定義19項目PASS」は仮に正しくても、実装・QC・QAのPASSへ変換してはいけない。

### P3.2 E系列

| 系列 | QA観測点 | 個別留意 |
|---|---|---|
| E01 Windows | CPU/ABI、権限、音声、字幕、ファイル、配布、復旧 | Windows優先は施工上の優先度のみ |
| E02 Linux | ディストリ/音声・画面環境、Wayland/X11、パッケージ、権限 | Windows/WSL結果を流用しない |
| E03 macOS | OS版/CPU、音声・画面権限、署名、配布 | Linux結果を流用しない |
| E04 Android | SDK/ABI、マイク/Bluetooth、共有、背景、端末許可 | エミュレーターと実機を区別 |
| E05 iOS | SDK/ABI、マイク/Bluetooth、共有、背景、配布制約 | シミュレーターと実機を区別 |
| E06 Web | ブラウザ×OS、権限、DOM、音声・カメラ、ファイル、ネットワーク | ネイティブと同一権限を前提化しない |

環境/端末ごとの実機確認は別列：CONFIRMED／NOT CONFIRMED／LIMITATION。QAの論理成立と実機確認を混同しない。許可・配布制約は仮想的成功で消滅しない。

各U要求についてE01-E06との適用行列を作る。OS機能が制約される経路は制約の根拠・代替体験・停止状態を明記し、無根拠な「対象外」で行列から消さない。対象環境全体の品質PASSは、その環境の適用対象と許可条件を全て監査した場合に限る。

### P3.3 検査データと異常系

- 言語：英⇄日を最初の具体的言語対照例とし、一般化を語る際は別言語ペアと非対応を追加検査。対応済み言語の保証下限を勝手に設定しない。
- 異常：入力欠落、途中取消、重複、ネットワーク遮断、音声回り込み、話者交差、暫定/確定到着逆転、文書配置不一致、モデル欠落、権限撤回、配送不明、部分保存、移行中断。
- 比較：同一仕様版と入力集合でRust実装・他OSアダプター・将来AICompiler版の外部同一性を検査。コード行・バイナリ一致を要求しない。
- 計測：仮定と観測を分け、遅延/資源の数値閾値は合意・根拠なしで決めない。

## P4 前提関係・保留の処理

1. MINIDORA-BETA公開実訳APIは未確認：W03の実訳成立をBLOCKED、外部構成は施工継続。独立版への拡張が必要ならMCR形式で依存変更要求を提出し、凍結βを変更しない。
2. 先行の未コミット差分、11スキーマ/13テスト/MCR-001はG0で実証できた場合のみ取り込む。所在不明なら未観測として保持し、新成果へ無断で算入しない。
3. RTranslator 3.0：当初の外側基盤採用方針と現行文書の参照候補扱いを照合。外部制御・UI・TTS・通信・モデル管理の責務単位で再利用を判断。第三者モデル/素材は別権利。
4. 技術候補の比較はG2で完了させる。Rustは暫定中心とし、Tauri2が全機能に不適なら代替OSアダプターを使う。論理契約を後退させない。
5. 外部契約、著作物、参加者通信、公開HDS境界に未解決の重大な権利問題があればその部分を停止。独立部分を施工継続する。
6. 工数・作業回数を完了基準にしない。途中コミットは復旧・証拠の単位であって製品受入ゲートではない。

## P5 施工の完了出力

Codexは次を一式で提出する：

1. 施工開始/終了HEAD、変更一覧、使用第三者ソースと版、技術選定・不採用理由。
2. 全W実装・結線対応表、全A/U/E受入行列、実施/未実施の全検査と再現手順。
3. 分離した失敗・停止・未確認・権限外・未実訳・未配送の一覧。
4. 証拠の環境・版・入力・期待・観測・ログ、品質・性能範囲。
5. AICompiler移管可能性：論理契約、Rust固有結合の場所、交換テスト、残る依存。
6. Ownerの判断要求と、独立最終検収のための差分・残余リスク。

終端区分：施工完了≠品質成立≠実訳成立≠製品受入≠公開許可。全体の未成立を明示して閉じる。
