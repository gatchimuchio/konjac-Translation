# こんにゃく翻訳 — 製品要求仕様（初期正本）

- 制定：2026-11-04
- 状態：構想／設計。**実装済み機能を表す文書ではない**。
- 製品：Konjac Translation（`konjacTranslation` / こんにゃく翻訳）
- 変更規律：[AGENTS.md](../AGENTS.md)、[意思決定記録](DECISIONS.md)

## 1. 主語・目的・成果

**主語：翻訳体験を一体化したマルチ翻訳プラットフォーム。** 駆動エンジン一般、ASRモデル、字幕プレイヤーそのものではない。

**目的：言語の壁によって生じる手間、遅延、情報損失、会話断絶を技術で解消し、言語をフリーにすること。** ユーザーに語学学習や各アプリ間の手作業を前提とさせない。例えば日本語話者と英語話者がそのまま話す、海外記事・動画・会議・資料を母語のように扱う、相手の言語で発信する、という連続した日常体験を対象とする。

「入力を別の言語に変換して終わり」ではない。**翻訳前後の入手・理解・応答・編集・利用・共有の動線全体**を製品の責任範囲とする。ただし利用者の意思、同意、原文確認と最終送信許可を奪わない。

## 2. 翻訳体験の全体射程

| 領域 | 例 | 期待する入出力 |
|---|---|---|
| 一般テキスト翻訳 | 入力、貼付け、共有テキスト、辞書的照会 | 自動言語判定候補、指定言語への訳、原文照合、コピー、読み上げ |
| 対面会話・通訳 | スマホの往復会話、複数話者、音声入力 | 自分／相手ごとの訳文・翻訳音声、話者別表示、応答の継続 |
| 音声・録音・ポッドキャスト | マイク、ファイル、録音 | タイムスタンプつき文字起こし、複数言語への訳、テキスト・音声出力 |
| 電話・オンライン会議 | 通話・会議アプリ連携 | 会話字幕、双方向通訳、会議文字起こし、翻訳議事録 |
| 動画・配信・学習教材 | プレイヤー、ストリーム、録画ファイル | 逐次字幕、字幕ファイル、言語別字幕・吹替、時間同期 |
| Web・ブラウザ | ページ本文、選択範囲、フォーム等 | 読みやすさ・リンク・DOM構造を保つ翻訳、必要箇所だけ翻訳 |
| 文書・電子書籍 | PDF/Word/Office/構造化ファイル | 見出し・表・段落・脚注等の関係、レイアウトを保つ訳文／書き出し |
| 画像・カメラ・画面 | 看板、メニュー、写真、スクリーンショット | OCRに基づく訳、原画像との位置対応・重畳、誤認識修正 |
| チャット・SNS・メール | 受信表示、下書き、送信直前確認 | 双方向訳、口調・相手・文脈保持、送信は利用者の明示操作 |
| 外部サービス・開発者 | API/SDK、許可されたアプリ連携 | 共通ジョブ形式に基づく翻訳・字幕・文書処理と結果取得 |

ここにない将来媒体も、**翻訳の入力・出力・体験**として追加できる構成にする。翻訳以外の汎用AI行動やOS操作をこの製品の目的へ勝手に追加しない。

## 3. 共通の体験契約

1. **言語設定の継続**：自分の優先言語、相手ごとの言語、表示／読上げ言語を継承し、明示的に変更できる。誤判定時は容易に修正可能とする。
2. **一つの仕事を複数形式へ**：同じ音声の原文 → 話者別文字起こし → 訳文 → 字幕／議事録／翻訳音声などを、対応関係を維持して得る。
3. **原文を失わない**：出典、原文、訳文、文脈、時刻、話者、用語、確定状態、改訂履歴を対応づける。結果は上書きせず版として扱う。
4. **文脈の保持**：単語や行を切り出して機械的に訳すだけでなく、関係性・話者・用語・前後発話と翻訳結果の整合性を検査する。保証できない場合は明示する。
5. **即時性と精度の区別**：途中表示は暫定、確定済み区間は固定。字幕の再翻訳・修正は版更新として提示し、表示のちらつきや内容の捏造を避ける。
6. **相手と環境に応じた提示**：字幕、読み上げ、画面重畳、文書、コピー／共有等、最適な出力先を選べる。利用者に毎回複数アプリの往復を要求しない。
7. **許可された操作のみ自動化**：マイク、画面、カメラ、ファイル、通話、翻訳サーバー、送信の権限は別管理。操作が成立しないOSでは無断回避しない。
8. **アクセシビリティ**：表示速度、字幕の大きさ、音声再生、片手操作、視覚・聴覚支援、キーボード操作等を対象にする。

## 4. 拡張の考え方

- **入力を増やす**：マイク、ファイル、Webページ、PDF、ブラウザ、外部API、カメラ／スクリーン／動画等。元媒体の権限・構造・時刻・配置を保持。
- **言語を増やす**：言語ペアだけでなく、1原文→複数の訳先、話者ごとの自動言語切替、方言・用語集を同一契約に置く。
- **出力を増やす**：表示字幕、翻訳音声、ファイル書き出し、オーバーレイ、字幕規格、読み上げ、APIレスポンス等。
- **利用環境を増やす**：Windowsを実機基準として先行検証しつつ、Web／Android／iOS／各種ホストアプリをプラットフォーム契約として射程に残す。
- **処理場所を増やす**：ローカル、LAN内、クラウドを条件付きで許容。ただしデータ送信先と処理場所が必ず分かり、同意なしで切替しない。

どの拡張も、**MINIDORAの翻訳駆動能力の実証がなければ製品として成立したと宣言しない**。必要な専用ASR/OCR/TTS等はあくまで入出力側の処理であり、意味判断・採否の別エンジンではない。

## 5. 非目標と禁止

- 「音声文字起こし＋スマホ同時通訳だけ」を最終仕様とすること。
- 翻訳領域を外れた汎用AIエージェント／独立したMINIDORA互換プラットフォームへ読み替えること。
- 入力・翻訳・出力の責務を再混合し、外側に第二の判断機構を追加すること。
- 基盤未実証のまま「多言語対応済み」「リアルタイム保証」「完全オフライン」「どの通話アプリでも録音可能」などと断言すること。
- 著作権・会議参加者の同意・端末のセキュリティ制約を無視した画面・音声取得や外部送信。
- 勝手な原文改変、隠れた自動送信・自動公開。

## 6. 受入可能な製品の状態

利用者は「翻訳したい場所・媒体・相手」を選ぶだけで、同じ言語設定・文脈・履歴のもとに訳を得られ、原文との対応や誤訳を確認・訂正できる。新しい媒体・言語・表示先の追加が**翻訳中核の改造なし**にできる。

これは完成条件であって現状の達成報告ではない。[受入検証](ACCEPTANCE.ja.md) と [工程](DELIVERY_PLAN.ja.md) を個別に満たす必要がある。
